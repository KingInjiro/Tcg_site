# TCG — сайт і адмінпанель

Статичний HTML-сайт із візуальним конструктором **GrapesJS** за адресою `/admin/`.
Текст редагується прямо на сторінці, блоки перетягуються мишкою. Зміни публікуються
у `KingInjiro/Tcg_site`, гілка `main`. Вхід — через GitHub з правом запису в репозиторій.

## Як працювати в редакторі

1. Відкрийте `/admin/` і натисніть **Увійти через GitHub**.
2. Виберіть сторінку ліворуч. Пошук знаходить її за назвою або адресою.
3. Двічі натисніть на текст, щоб його переписати. Перетягніть блок із лівої панелі
   або натисніть на нього, щоб додати до вибраного елемента чи в кінець сторінки.
4. Виберіть елемент: праворуч доступні шрифт, колір, розмір, відступи й рамка.
   Для зображення є кнопка **Вибрати зображення**; для кнопки/посилання — адреса
   і список сторінок сайту.
5. **+** біля «Сторінки» створює нову сторінку. Введіть назву; адреса латиницею
   запропонується автоматично. Доступні проста сторінка, сторінка послуг та копія
   поточної. За бажанням залиште позначку, щоб додати посилання внизу поточної сторінки.
6. Перевірте **Перегляд**, вигляд на телефоні, скасування/повторення дій.
7. **Опублікувати** зберігає всі змінені сторінки й нові зображення разом.
   На Vercel сайт оновиться після успішного розгортання цього коміту.

Нові сторінки мають адресу `/назва-латиницею/` (наприклад, `/nashi-posluhy/`).
Нові шаблони використовують те саме оформлення й меню, що й решта сайту.
Наявні файли не перезаписуються при виборі зайнятої адреси. Видалення сторінок
у цьому інтерфейсі не передбачено.

Чернетки зберігаються у відкритій вкладці до публікації. Перед закриттям браузера
скористайтеся **Резервна копія**. Файл JSON можна повернути через **Відновити**, якщо
версія сайту відтоді не змінилася. Токени входу в резервну копію не потрапляють.
Коли інший редактор уже змінив сайт, публікація зупиниться без перезапису його правок.

Для нового зображення використовуйте PNG, JPG, GIF або WebP до 2 МБ. Воно
завантажиться разом зі сторінками під час публікації. Сумарна публікація обмежена
8 МБ текстових даних (включаючи base64 зображень).

## Що оновлено

Сторінки мають структуру HTML5: шапка, навігація, основний вміст і підвал.
Макет використовує CSS Grid/Flex і підлаштовується під телефон. Широкі таблиці
прокручуються у власному блоці, а не розтягують усю сторінку.

Збережено логотип, білі блоки вмісту, помаранчеві посилання, графіку жовтої шапки та
шість верхніх GIF-кнопок 90×25 px. Ліве меню тепер має живі написи 18–19 px,
кнопки заввишки щонайменше 58 px на комп’ютері. При наведенні з’являється м’який
жовтий фон із тонким контуром; поточний розділ має насиченіший фон та помаранчеву
смужку зліва. Підсвічування намальоване CSS, без старої розтягнутої GIF-картинки.
На телефоні меню відкривається кнопкою «Разделы сайта»;
без JavaScript воно залишається доступним. Основний текст — 17 px.
Шапка з жовтою графікою займає всю ширину екрана; обмежується лише ширина
її внутрішнього вмісту. Головна має окремі блоки напрямів роботи, опис автоматизації
та інформацію про компанію. Послуги подані секціями з окремими переходами,
каталоги статей і документів — плитками, контакти — згрупованими блоками,
новини — списком із датами та розкривним архівом. Дубльований список статей прибрано.
Спільне оформлення — `themes/site.css`, поведінка — `themes/site.js`.

Скриншоти локальної збірки від 30.09.2026: [головна на комп’ютері](preview-images/home-desktop.png),
[сторінка послуг](preview-images/services-desktop.png), [головна на телефоні](preview-images/home-mobile.png).

Прибрано рекламні вставки, лічильники, застарілу фінансову стрічку й непрацездатні
форми FrontPage. `/search/` шукає у вмісті сторінок за індексом, який створюється
під час кожної збірки. `/feedback/` готує лист у поштовій програмі або дозволяє
скопіювати його текст. **Надсилання потрібно підтвердити у своїй пошті** — сайт
не повідомляє про доставку й не надсилає листи сервером.

Договори XML і довідники CHM мають версії для читання в браузері в розділі
«Загрузки и документы», кнопку друку / збереження PDF та посилання на оригінал.
Старі матеріали й ціни не переписані під виглядом актуальних: архівні сторінки
мають пояснення. Для оновлення цін потрібні дані власника сайту.

Калькулятори та інші скрипти не виконуються всередині полотна конструктора.
Їх перевіряють у **Перегляді** або на опублікованій сторінці.

## Адреси без `.html`

| Стара адреса | Нова адреса |
| --- | --- |
| `/index.html` | `/` |
| `/contacts.html` | `/contacts/` |
| `/services.html` | `/services/` |
| `/ListPage/Pege05.html` | `/articles/backup/` |
| `/Download.html` | `/downloads/` |

Повна відповідність зберігається в `themes/routes.js`. Файли в репозиторії
зберігають свої назви, щоб конструктор і історія редагувань продовжували працювати.
`npm run build` створює справжні каталоги, наприклад `dist/contacts/index.html`.
Тому нові адреси працюють на статичному хостингу зі стандартним `index.html`.
Внутрішні переходи, результати пошуку й нові сторінки конструктора використовують
чисті адреси. Зайняті адреси й службові назви не можна використати для нової сторінки.

На Vercel та Node-сервері старі імена перенаправляються кодом 308. У статичній
збірці залишені HTML-сторінки перенаправлення: JavaScript зберігає також параметри
адреси й перехід до розділу після `#`; без нього працює HTML-перенаправлення.
Відкритий вручну `/index.html` у звичайному статичному хостингу прибирається
з адресного рядка через JavaScript; без нього головна все одно відкривається.

## Як передати готовий сайт на інший хостинг

Для публічних сторінок потрібен хостинг HTML, CSS і JavaScript з підтримкою
`index.html` у каталогах. **Node.js на комп’ютері батька для цього не потрібен.**
Готову збірку можна отримати через GitHub:

1. Після злиття змін відкрийте репозиторій → **Actions** → **Website checks and static build**.
2. Виберіть успішний запуск для останнього коміту `main` (зелена позначка).
   Якщо потрібна нова збірка, натисніть **Run workflow**, виберіть `main` і запустіть її.
3. Унизу сторінки запуску, у **Artifacts**, завантажте **tcg-website-static**.
   Для завантаження увійдіть у GitHub. Артефакт зберігається 14 днів;
   після цього запустіть workflow повторно.
4. Розпакуйте ZIP. Зробіть резервну копію наявного сайту на хостингу.
5. Через файловий менеджер хостингу або SFTP завантажте **вміст архіву**
   в кореневу папку сайту: поряд мають лежати `index.html`, `contacts/`, `themes/`,
   `images/` тощо. Назва кореневої папки залежить від хостингу.
6. Перевірте `/`, `/contacts/`, `/search/`, `/downloads/` і стару адресу `/contacts.html`.

Архів **Code → Download ZIP** містить вихідний проєкт; для перенесення готового
сайту використовуйте артефакт вище або вміст `dist`, отриманий після `npm ci`
і `npm run build`. Сайт розрахований на корінь домену, а не вкладену папку `/tcg/`.

**Вхід у конструктор має окремі вимоги.** Публічний сайт працює статично,
але GitHub-вхід використовує серверні `/api/auth` і `/api/callback`.
На Vercel вони вже входять у проєкт; на Node.js-хостингу їх обслуговує `server.js`.
Самого копіювання `dist` на хостинг лише з HTML/PHP недостатньо для цього входу.
Для повністю онлайнового редагування на такому хостингу потрібно визначити,
де працюватиме авторизація і як нові збірки потраплятимуть на сервер.
Можливості хостингу батька ще не підтверджені.

Після наступних публікацій через GitHub для звичайного статичного хостингу
потрібно завантажувати нову збірку й оновлювати файли. Цей workflow лише готує
архів і сам не змінює сайт на сторонньому хостингу.

На головній у блоці курсів є конвертер USD/EUR/UAH. `themes/calculators.js`
запитує курс на поточну дату в Києві через [API НБУ](https://bank.gov.ua/ua/open-data/api-dev),
показує дату відповіді та рахує `сума × курс вихідної валюти / курс цільової`.
Курс UAH дорівнює 1. Відсутні, некоректні чи неактуальні дані блокують розрахунок;
кнопка оновлення повторює запит, тайм-аут — 10 секунд. Вбудованих запасних курсів немає.

На `/articles/backup/` калькулятор оцінює місце для повних резервних копій:
`обсяг однієї копії × кількість копій × (1 + запас / 100)` у ГБ.
Стиснення, дедуплікація та службові дані не враховуються; розрахунок локальний.
Обидва калькулятори приймають десяткову крапку або кому. У полотні конструктора
скрипти не запускаються; розрахунки працюють у перегляді опублікованої сторінки.

## Локальний запуск

Потрібен Node.js 24.

```sh
npm ci
npm run dev
```

Сайт: <http://localhost:3000/>. Редактор без GitHub-входу:
<http://localhost:3000/admin/?local=true> → **Відкрити локальний редактор**.
Другий процес для візуального редактора не потрібен. Зміни записуються у локальні
HTML-файли; вони не надсилаються в GitHub автоматично. Локальний API змін доступний
тільки в явному dev-режимі, на loopback-хості та для запитів з того самого origin.
В production/Vercel цього API немає.

## Налаштування входу на Vercel

`vercel.json` задає `npm run build`, каталог `dist` і заголовки адмінпанелі.
`api/auth.js` та `api/callback.js` виконуються як серверні функції Vercel.
Окремий сервер авторизації не потрібен.

1. У [GitHub → Settings → Developer settings → OAuth Apps](https://github.com/settings/developers)
   створіть **New OAuth App**.
2. Вкажіть фактичний основний домен сайту:
   - **Homepage URL:** `https://ВАШ-ДОМЕН`
   - **Authorization callback URL:** `https://ВАШ-ДОМЕН/api/callback`
3. Скопіюйте **Client ID** і створіть **Client Secret**.
4. У Vercel → проєкт `tcg-site` → Settings → Environment Variables додайте:

   | Змінна | Значення |
   | --- | --- |
   | `CMS_ORIGIN` | `https://ВАШ-ДОМЕН` без `/admin` та інших шляхів |
   | `GITHUB_CLIENT_ID` | Client ID OAuth-застосунку |
   | `GITHUB_CLIENT_SECRET` | Client Secret OAuth-застосунку |

5. Застосуйте змінні до **Production** і виконайте нове розгортання.
6. Відкрийте `https://ВАШ-ДОМЕН/admin/`, натисніть вхід через GitHub і використайте
   обліковий запис із правом запису в `KingInjiro/Tcg_site`.

Секрет задається лише в налаштуваннях сервера, не в `admin/config.yml`, HTML
чи комітах. Запитується scope `public_repo`, оскільки цей репозиторій публічний.
GitHub OAuth із цим scope не обмежується одним публічним репозиторієм.
Якщо перевіряєте вхід на Preview-домені, використайте окремий OAuth App,
точний Preview-домен і відповідні Preview-змінні. Production OAuth-налаштування
не є універсальним входом для всіх Preview-адрес.

## Формат збереження та сумісність

Кожна публікація містить готовий HTML та дані блоків у
`.tcg-editor/<шлях-сторінки>.json`. Ці дані потрібні для повторного відкриття
конструктора; вони не копіюються у публічний `dist`. HTML і JSON потрапляють
в один коміт через GitHub Git Data API; оновлення гілки не використовує force.
Якщо HTML змінено іншим інструментом, редактор перевіряє його SHA-256 і імпортує
актуальний HTML замість застарілого проєкту.

Саме відкриття сторінки не змінює файл. Після візуального редагування GrapesJS
нормалізує HTML і записує свої стилі; побайтова тотожність старого HTML не обіцяється.
Зберігаються метадані голови документа, шляхи зображень, посилання та службові вставки.
Для аварійного редагування HTML попередня Decap-адмінка залишена на `/admin/legacy.html`.
Її фіксований список сторінок не містить нових сторінок конструктора.

### Відновлені файли та зображення

Редактор перевіряє вміст файлів, а не лише розширення `.html`. Двійкові документи,
текст із пошкодженим кодуванням і збережені відповіді Apache «404 Not Found»
не пропонуються як сторінки та не потрапляють у публічну збірку. Перевірка також
виконується перед імпортом і публікацією. Нові справні HTML-сторінки, зокрема
в `Docs/` та `ListPage/`, знаходяться автоматично.

Під час перевірки 24.09.2026 відновлено оригінали з `http://www.tcg.com.ua/`:

- `PCTarf.files/image002.gif`, `image004.gif`, `image006.gif` — ілюстрації тарифів;
- `images/Help.jpg` — ілюстрація на сторінці комплексного обслуговування;
- `Docs/Sno_for_Buh_ua.ert` — документ 1С, який помилково був збережений як HTML.

Логотип `images/logo.gif` відновлено зі справної вбудованої копії у `TEconom.html`.
Під час модернізації 29–30.09.2026 додатково відновлено справні оригінали:

- [UniversTCG.chm](http://www.tcg.com.ua/Docs/UniversTCG.chm) — SHA-256
  `c844fe0069795e4e124e8308db4a791755b9053057b8206f5b7e145a1defdc7a`;
- [NalogNaReklTCG.chm](http://www.tcg.com.ua/Docs/NalogNaReklTCG.chm) — SHA-256
  `91605c43ed7ebd782ced652a00bcaedaad79cd81290ba4dfcf6a05d11c1923cb`.

Обидва CHM пройшли перевірку цілісності 7-Zip. Ілюстрації з формату VML
для Internet Explorer перенесено у звичайні зображення. Текст трьох договорів
у HTML звіряється з усіма текстовими вузлами оригінальних Word XML, без службових
колонтитулів друку. Це технічне перетворення, а не оновлення змісту договорів.

Старе посилання `/Docs/Sno_for_Buh_ua.html` перенаправляє на завантаження `.ert`.
Пошкоджені імпортовані HTML-файли залишені в репозиторії для історії, але недоступні
як публічні сторінки. У репозиторії немає 17 ZIP-архівів звітності, згаданих на
старій сторінці завантажень. Вони позначені як відсутні, замість хибних кнопок
завантаження. Для відновлення потрібні справжні ZIP-файли. Перевірка завантаження
документа 1С не означає перевірку його виконання в програмі 1С.

OAuth-налаштування залишаються тими самими: `/api/auth`, `/api/callback` і три змінні
з розділу налаштування входу. Токен GitHub зберігається лише в пам’яті вкладки. Після перезавантаження
потрібно знову натиснути кнопку входу. Збережений JSON не містить токенів або секретів.

Локальний Express-сервер у production-режимі потребує оновлення коду та перезапуску
після публікації через GitHub.

## Запуск на Node.js сервері

Скопіюйте `.env.example` у `.env`, задайте ті самі три OAuth-змінні та запустіть:

```sh
npm ci
npm start
```

`npm start` створює `dist` перед запуском. Порт — `PORT` або `3000`.
HTTPS має завершуватися на вашому reverse proxy. Для локального OAuth-тесту
можна задати `CMS_ORIGIN=http://localhost:3000` та відповідний callback URL
у окремому тестовому OAuth App.

## Перевірки та діагностика

```sh
npm test
npm run build
```

Браузерна перевірка створює ізольовану тимчасову копію сайту й не змінює
робочі сторінки або GitHub. Після встановлення Chromium:

```sh
npx playwright install chromium
npm run test:browser
npm run test:content
npm run test:calculators
npm run test:modern
```

Перша команда перевіряє імпорт наявних сторінок, фактичне декодування картинок
у конструкторі, зміну тексту, перетягування блоків, нові сторінки, фото, копіювання,
відновлення чернеток і конфлікт публікації. Друга відкриває сторінки готового `dist`
на статичному сервері без виправлення регістру адрес: перевіряє UTF-8, завантаження
локальних ресурсів і декодування кожного файлу зображення в Chromium.
Третя перевіряє розрахунки обох калькуляторів, помилкове введення, відмову
при недоступних або застарілих курсах та повторне завантаження. Відповіді НБУ
в цих тестах контрольовані; це не перевірка доступності живого API.
Четверта перевіряє чисті адреси на звичайному статичному сервері, усі сторінки
на трьох ширинах екрана, меню, пошук, підготовку листа та друк довідників.
Зовнішні сайти з архівних посилань не входять до локальної перевірки.
Для власного Chromium можна задати `TCG_BROWSER_EXECUTABLE`.
Модульні набори запускаються послідовно, оскільки використовують спільний `dist`.

Тести перевіряють OAuth state/PKCE, відмову без налаштувань і прав запису,
безпечну передачу результату до редактора, атомарний GitHub-коміт, конфлікти змін,
обмеження шляхів, захист локального API та відсутність серверних файлів у публічній збірці.
Окремо залишається тест старого raw-формату Decap; він не є тестом візуального імпорту.
Тести OAuth використовують імітацію відповідей GitHub; вони не замінюють
перевірку реального входу після налаштування OAuth App.

- **«Вхід ще не налаштовано»**: перевірте три змінні та повторне розгортання.
- **Сеанс входу недійсний**: відкрийте CMS на домені з `CMS_ORIGIN` та почніть
  вхід повторно; дозвольте cookies й спливне вікно для цього сайту.
- **Немає права редагувати**: перевірте GitHub-акаунт і його доступ до репозиторію.
- **Зміни опубліковані, але їх ще немає на сайті**: перевірте коміт у `main`
  та завершення пов'язаного deployment у Vercel.
