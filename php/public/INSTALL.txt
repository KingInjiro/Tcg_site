TCG — автономний сайт і PHP-редактор

1. Спочатку збережіть копію старого сайту. ZIP призначений для чистого встановлення у корінь окремого домену. У корені мають лежати index.html, admin, themes, images та інші папки з архіву. Не завантажуйте весь GitHub-репозиторій.
2. Розпакуйте один ZIP через файловий менеджер хостингу або завантажте вже розпаковані файли. ZIP після розпакування видаліть із публічної папки.
3. Відкрийте https://ваш-домен/admin/compatibility.html. Для редактора потрібен PHP 8.2–8.5; для повного редактора — DOM, fileinfo, GD, сесії, криптографічні функції, локальні блокування та атомарна заміна файлів. Потрібен HTTPS із чинним сертифікатом.
4. Відкрийте https://ваш-домен/admin/. Введіть окремий ключ із файлу activation.txt, створіть власні логін і пароль. Файл з ключем не завантажуйте на сервер. Не передавайте його стороннім.
5. Редагуйте текст подвійним натисканням. Нові сторінки створюються кнопкою +. У налаштуваннях є перейменування й видалення; у верхній панелі — меню й попередні версії. Натисніть «Опублікувати», щоб відвідувачі отримали зміни. Завантажувати нові архіви після кожного редагування не потрібно.
6. Для контактних форм відкрийте «Пошта», внесіть SMTP-дані від поштового провайдера, збережіть і перевірте TLS/авторизацію. Потім надішліть власне повідомлення через форму сайту. Перевірка SMTP сама листа не надсилає й не доводить доставку в скриньку. Без налаштувань форма чесно повідомляє про недоступність.
7. Виходьте з адмінпанелі після роботи. Паролі, поштові дані й сесії не входять до версій сторінок і не розміщуються у публічній папці.

Умови: Linux/Apache або сумісний вебсервер; встановлення в корінь document root; PHP повинен мати право створити приватну папку ПОРЯД із коренем домену, а не всередині нього. Папка з даними — .tcg-<ідентифікатор> — створюється автоматично. Якщо open_basedir або права не дають це зробити, редактор не активується. Публічні HTML-сторінки продовжують працювати. Встановлення у підпапку та сховище всередині web root у цьому релізі не підтримуються.

Не потрібні: Node.js/npm, Composer, MySQL, SSH, root, GitHub, Vercel або стороннє сховище на production. Ресурси редактора входять до ZIP. Курси/новини, якщо вони використовують зовнішні інформаційні джерела, як і раніше залежать від доступності цих джерел.

Обмеження: до 2 МБ на зображення, до 4096 пікселів за стороною й 8 млн пікселів загалом; до 2 МБ HTML на сторінку, 4 МБ даних редактора на сторінку, 8 МБ змін за запит. Приватне сховище обмежене 40 МБ. Зберігаються три попередні версії без копіювання всіх ресурсів сайту. Перед великими змінами перевіряється місце для staging і відновлення. Фактична квота облікового запису хостингу може бути меншою за показник вільного місця файлової системи; невдалий запис не вважається успішною публікацією.

Реліз не є універсальним для будь-якого старого сервера. Діагностика старішого PHP не означає, що редактор підтримує його. Реальний невідомий хостинг потрібно перевірити після початкового завантаження. Сумісність не замінює подальші оновлення безпеки PHP та адмінпанелі.
